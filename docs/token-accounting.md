# Token accounting

The proxy records `usage` returned by Anthropic in JSON responses and SSE `message_start` / `message_delta` events. These are labeled `ACTUAL`. The context classifier's UTF-8 bytes divided by four and the renderer's patch count are `ESTIMATED`; neither is a measured baseline. Adaptive image decisions require original and final counts from Anthropic's token-count endpoint before upstream dispatch. Set `measurement.counterfactual_tokens: true` to make an optional nonblocking count for other transformed requests when an API key is present. Token-count results are provider estimates, and a count failure leaves the field empty. A valid savings claim also needs cache-adjusted cost and task accuracy.

Cache reads and writes are stored when present in provider usage. `final_input_tokens` is the sum of uncached input, cache reads, and cache writes when the response reports them; the split remains available separately. Missing values display as unavailable rather than zero. Output tokens from a transformed run are not a baseline for a separate run.
