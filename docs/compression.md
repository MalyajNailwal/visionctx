# Compression

`passthrough` forwards original body bytes. `text` can minify tool-result JSON and collapse exact consecutive duplicate log lines while preserving the first line and a repeat count. An opt-in extractive summary keeps log heads, tails, and diagnostic lines, inserting omission markers. `image` can render eligible tool-result strings when image output is explicitly enabled. `adaptive` compares eligible estimated token counts using configured thresholds and conservative risk gates. If it selects an image, it also checks the original and final requests with Anthropic's token-count endpoint before sending; a missing count or no reduction restores the original request. System prompts, user prompts, assistant messages, source code, secret-bearing blocks, and unsupported content paths stay as text. These modes are experimental except passthrough.

The strategy interface exposes eligibility, token estimate, compression, restoration, and metadata. Repeated-line compression and extractive summaries are lossy; they are reversible only while the original safe source is still available in memory or captured on disk. The original source remains in memory during one request for a pre-dispatch fallback. It is persisted only when capture is opted in and no secret pattern is detected. Compression decisions are visible in the inspector. Image conversion and summarization require task-level A/B evaluation before they can be recommended.
