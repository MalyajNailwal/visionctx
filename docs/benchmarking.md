# Benchmarking

There are no published VisionCtx performance or accuracy results. A meaningful A/B run must use the same task, model, tool environment and temperature across baseline, text, image and adaptive modes; record each run's answer, code/test outcome, tool-call correctness, provider usage, cache split, and wall time. Use multiple trials to detect variance. Keep fixtures separate from live dashboard data and label synthetic data clearly.

`node dist/apps/cli/index.js benchmark --model <exact-model-id>` runs four checked-in tasks through each of the four modes: 16 paid API calls. It requires `ANTHROPIC_API_KEY`. The command reports raw answers, exact-answer and tool-call correctness, provider usage, status and latency for each trial. Results are stored in SQLite and appear on the dashboard's Benchmarks page. These fixtures cover JSON analysis, log analysis, a Python loop bug, and stack-trace interpretation. They are a starting suite, not evidence of general coding accuracy. The harness currently runs one trial per arm and does not calculate cost until `pricing.yaml` has an exact model rate. Before publishing savings, repeat trials, add code-execution grading, and compare cache-adjusted cost. Never present a local image patch estimate as a billed total.
