## Long-term Knowledge

### Architecture

<!-- lore:01a11511-4490-75e2-80f3-591a8b055f1f -->
* **VisionCtx native Messages proxy compatibility**: Chose a transparent native Node HTTP Messages proxy over an Anthropic SDK wrapper because Claude Code, OpenCode, and direct API clients require protocol compatibility plus status/header and SSE fidelity. Passthrough is the default; inspection, optional compression, SQLite metadata/events, dashboard views, and opt-in image rendering are layered around the same flow.

<!-- lore:01a11511-4511-7fab-95e8-841c37199bc5 -->
* **VisionCtx sensitive-content and dashboard boundaries**: Chose bounded in-memory inspection plus opt-in SQLite full-body capture over always persisting request bodies because coding-agent payloads can contain credentials and unbounded tool output. Redaction-flagged blocks must never be transformed, persisted, or rendered. By default retain metadata/events and sanitized diagnostics only; full-body capture requires explicit configuration. The proxy and dashboard currently use loopback binding as their authentication boundary because dashboard authentication is absent, so network exposure must not be treated as safe.

### Gotcha

<!-- lore:01a11511-44d5-704c-9193-e13740c9cf2b -->
* **Adaptive bytes/12 dense-text trap**: Adaptive image eligibility is stricter than \`image.canHandle\`: only \`LOGS\` and \`TERMINAL\_OUTPUT\` qualify; \`TOOL\_RESULT\` and \`DOCUMENTATION\` remain ineligible. Trap: \`ceil(bytes / 12)\` looks authoritative because it cheaply estimates image tokens, but it assumes repetitive or formatting-heavy text and underestimated a dense-log rendering by about 3.5× in the reviewed estimate. Compare it and rendered-page counts with exact provider counts; restore the original whenever counts are unavailable or not lower. OCR-sensitive UUIDs, ports, and error codes add semantic risk despite faithful pixels. Retry transformed upstream 400s matching image/vision/media/resolution once with the original and record \`FALLBACK\_USED\`.

<!-- lore:01a11511-44bc-72c2-8439-d4534c0c0a30 -->
* **Anthropic cache\_control detection and strategy boundaries**: Chose leaving the cacheable prefix unchanged over compressing every large block because Anthropic hashes ordered \`tools → system → messages\`; pre-breakpoint rewrites can invalidate cache and raise cost. Protect blocks with top-level \`obj.cache\_control\`; otherwise protect the last message containing \`"cache\_control"\` and every earlier message. The top-level check is defensive because Anthropic normally marks content blocks. Trap: nested \`JSON.stringify(message).includes('"cache\_control"')\` looks sufficient because it catches arbitrary depth, but it ignores JSON structure; use recursive traversal with explicit paths.

<!-- lore:01a11511-44f4-768b-a9c1-daa1a33eb148 -->
* **benchmark harness one-trial accuracy limits**: \`benchmark --model \<exact-model-id>\` runs the checked-in 4 fixtures × 4 modes, or 16 paid calls. Trap: the exact-answer, tool-call, latency, and provider-usage scoring looks statistically strong because it is comprehensive, but there is only one trial per arm. Fix: label results fixture-level A/B evidence—not general coding accuracy or verified savings. Require repeated trials, executable correctness checks, a real baseline, current rates, and cache-adjusted comparison before publishing cost claims.
